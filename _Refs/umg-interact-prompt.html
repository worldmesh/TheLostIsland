1Что такое 9-slice

Это способ растянуть картинку-рамку на любой размер так, чтобы углы не превратились в овалы, а толщина рамки осталась одинаковой. Текстура режется на 9 кусков четырьмя линиями:

Углы не тянутся никогда · края тянутся по одной оси · центр по обеим

Как включить в UMG

Выделить Image → в Details блок Appearance → Brush:

ПолеЗначениеСмысл
Draw AsBoxвключает 9-slice (по умолчанию стоит Image — вот тут и ломается)
Margin4 числа 0…1доля от размера текстуры, а НЕ пиксели. 0.22 = 22%
Главная путаница: Margin здесь — это не отступ снаружи, как в CSS. Это линии разреза внутри текстуры. Ставить одинаковые значения во все четыре поля, если рамка симметричная.
ТекстураDraw AsMargin
T_KeycapBox0.22
T_Panel_DarkBox0.15
T_Frame_SelectedBox0.25
T_HairlineImage— (тянуть только по ширине)
T_Leader_Node (ромб)Image— фиксированный размер, не тянуть
T_Leader_ElbowImage— фиксированный, не тянуть

3Правильная иерархия

Ключевая замена: внутри Anchor ставим Canvas Panel, а не Overlay. Canvas даёт точные координаты каждому куску — именно этого не хватало.

SizeBox «Anchor» ← его двигает Tick. Canvas Slot: Alignment 0.5 / 0.5 └── Canvas Panel «Inner» Width Override 520, Height Override 260 ├── Image «Node» ромб. Anchors 0.5/0.5 · Align 0.5/0.5 · Pos 0,0 · 24×24 ├── Image «Elbow» выноска. Anchors 0.5/0.5 · Align 1/0.5 · Pos −12,+6 └── SizeBox «LabelBox» Anchors 0.5/0.5 · Align 1/0 · Pos −78,+26 └── Overlay ├── Image «Panel» T_Panel_Dark · Draw As Box · Margin 0.15 └── Vertical Box «Content» Padding 14,10,14,10 ├── Text «Title» ← Info.DisplayName ├── Image «Rule» T_Hairline · Height 1 · Padding 0,6 └── Horizontal Box «Action» ├── SizeBox 28×28 │ └── Overlay │ ├── Image «Key» T_Keycap · Draw As Box · Margin 0.22 │ └── Text «E» Justification Center └── Text «ActionText» ← Info.ActionText · Padding слева 8
Description больше не нужен — описания уехали в дневник. В подсказке остаются только имя и действие, вёрстка от этого заметно упрощается.

Как это выглядит

Ромб сидит в точке попадания трейса, плашка висит слева-снизу

4Почему в игре «появляется непонятно где»

Самая вероятная причина — Anchors у Canvas Slot. Если у Anchor якоря растянуты (Min ≠ Max) или стоят по центру, нода Set Position начинает означать совсем другое, и плашка уезжает.

Выделить Anchor в иерархии, в Details блок Slot (Canvas Panel Slot):

ПолеЗначениеЗачем
Anchorsлевый верхний угол (0,0)тогда Position — это пиксели от левого верхнего края экрана, ровно то, что отдаёт Project World Location to Widget Position
Alignment0.5 / 0.5позиция считается от центра ромба, а не от угла блока
Size To Contentвключитьиначе размер берётся из Offsets и Set Position конфликтует с ними

Про «трейс пробивает очень далеко» — это нормально и не баг. TraceDistance = 1000 задаёт длину луча, но цель засчитывается только если персонаж ближе MaxInteractDistance = 300. Луч длинный специально: камера в третьем лице висит позади персонажа, и короткий луч не доставал бы даже до него.

Порядок проверки

  • Anchors у Anchor = верхний левый угол, Alignment 0.5/0.5 — проверить первым делом
  • Деление Screen Position на Get Viewport Scale — на месте?
  • Второй Branch по bool из Project World Location... — если его нет, при объекте за спиной координаты становятся мусором
  • InteractionBox → Collision → Visibility = Ignore, иначе ромб садится на невидимый бокс, а не на меш
  • ZOrder виджета — если WBP_StatusLine добавлен в Viewport позже и на весь экран, он может перекрывать
